# Try Fullbleed in a sample store

[Open the browser demo](https://playground.wordpress.net/?blueprint-url=https://raw.githubusercontent.com/fullbleed-engine/fullbleed-commerce/main/playground/blueprint.json)

The demo starts a disposable WordPress Playground with WooCommerce, the free
Fullbleed plugin and two fictional, unpaid orders. No account, payment or store
connection is needed. Initial setup downloads WordPress and WooCommerce and can
take a minute or two.

1. Select **Generate PDF** to download the first sample order summary.
2. Select **Customize selected document**. Double-click a heading in the visual
   editor, or switch to **HTML / CSS** and paste your print styles.
3. Select **Preview PDF**, then **Save template**. Generate the order again to
   see the saved design in an actual Fullbleed PDF.
4. Try **Long order** to see how a 32-item order flows across pages. Change the
   document type to make a packing slip, with its own saved template.

Use **Export template** to keep a JSON copy of your design. The sample store is
temporary; do not enter customer information, payment details or service tokens.
Outgoing mail, WordPress networking, cron and WooCommerce tracking are disabled.
The browser still downloads the public code needed to start the demo.

This demonstrates the free editor and browser rendering. The Pro add-on's email
attachments and customer downloads require a separate server renderer and are
not enabled in Playground. See [automation setup](../automation/README.md) and
the [production product plan](../docs/product-plan.md) for the implemented
workflows and remaining paid-launch requirements.

## Install the preview on your staging store

Download the free plugin ZIP from the
[preview release](https://github.com/fullbleed-engine/fullbleed-commerce/releases/tag/v0.1.0-alpha.1).
With WooCommerce active, use **Plugins → Add New → Upload Plugin**, activate
Fullbleed, then open **WooCommerce → Fullbleed documents**. No Node or PDF service
is needed for the free plugin. Use staging data while evaluating this alpha.

## Reproduce and maintain the demo

`blueprint.json` is generated by `node tools/build-playground.mjs` from
`demo-plugin.php`, `seed.php` and the package version. Demo helpers are separate
from both distributed plugin archives. The Blueprint pins WooCommerce and the
Fullbleed release; WordPress selects the current patch of the pinned major.

After building and packaging the plugins:

```sh
node tools/build-playground.mjs --check
node tools/check-playground.mjs
```

The runtime check uses a disposable local WordPress and the exact release ZIP
bytes. It checks synthetic orders, HPOS, preserved totals and suppressed outgoing
mail/networking. `--serve` keeps that sample store on loopback port 9488 for
`python tools/check-playground-browser.py`. That browser check uses a separate
headless Chrome profile and exercises real PDF downloads, template editing,
persistence, pagination and mobile layout.

The public demo also needs a real-browser check after publishing the release
assets. Run the same browser script with `--url` and the public demo URL above;
retain the Blueprint and ZIP hashes with the result. Recheck after changing the
Blueprint, a pinned dependency or the release package. Do not replace published
ZIPs under an existing version.

The public link uses the documented
[WordPress Playground Blueprint URL mechanism](https://developer.wordpress.org/playground/blueprints/using-blueprints/).
